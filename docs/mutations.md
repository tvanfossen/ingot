# Mutation record: contract mode, variants and legacy key IDs

Every mechanism of contract mode (`src/contract/`) and of the legacy key-ID and key-list paths
(`src/model/`) has a single-mechanism mutation below and the tests that kill it. A mutation is
applied alone, `cargo test --bin ingot --test contract_mode --test contract_refusals --test
table_types` runs, and the file is restored. Status is the result on this branch: every one is KILLED. A `\n` in a cell is a newline.

## Removed as equivalent (no mutation can apply)

| Code removed | Why it was equivalent |
|---|---|
| `f.is_finite() &&` in `value::encode_float` | a non-finite f64 is non-finite as f32 too |
| `&& old.ty == new.ty` in `previous::key_unchanged` | the type is bits 6..3 of the ID, which is compared |
| `g.key.is_none() &&` in `rights::cell` | a key grant has no namespace (`check_grants` refuses one with both), so `scope_matches` never matches it |
| the owner count in `refuse_rights::heartbeats` | two principals sharing a heartbeat cannot both be its only writer, so the writer check already refuses it |
| the key-position fallback in the legacy `encode_key` | positions were stamped before filtering in `main::run`, so the fallback was unreachable from the binary; positions are now stamped once in `DataModel::from_toml` |
| the TRACE_ENABLE entry of the release review's sensitive roles | TRACE_ENABLE is required from the first contract with exactly one writer (R-V5); previous principals keep their rights in a minor (R-V8); the role cannot move within a major (W1). A new principal can therefore never write it in an accepted model |
| the "gives X a second number" refusal of a variant enum | a resolved enum is keyed by name, so one name with two numbers cannot occur; the refusal only fired, wrongly, when a base name moved to a new number in a particular order |

## Gaps the sweep found and closed

- Refusals added (spec section 8, row G): a class-only grant and a grant whose scope covers
  no key (both were accepted and granted nothing); a namespace name declared by two files.
- `contract.json` showed a class default interval on non-deferred keys; the tables and the
  JSON now share `Key::effective_deferred_ms`.
- Legacy key lists: hex-ID entries never matched (no encoded ID was passed); they now match
  the key's encoded ID in include, exclude and persistent lists.
- Variants (REQ-ING-TIV-015/016): a contract.json from an ingot without wire strings must
  still be checked through enum values alone; a dedicated test reads such a snapshot back.
